## 1. System Overview

TokenFlow AI is a two-tier web application:

| Layer | Technology | Entry point |
|-------|-----------|-------------|
| Backend | Python 3.12 / FastAPI | [`main.py`](main.py) — `uvicorn main:app` |
| Frontend | Next.js (TypeScript) | [`codemap-ui/next.config.ts`](codemap-ui/next.config.ts) |
| Orchestration | Docker Compose | [`docker-compose.yml`](docker-compose.yml) |

The backend exposes two API routes:

- `POST /api/analyze-structure` — reads a caller-supplied filesystem path and
  returns a hardcoded payload that lists mock service statuses.
- `POST /api/provision-sandboxes` — returns a hardcoded log describing sandbox
  provisioning steps. No actual sandboxes are created by this route.

The onboarding pipeline in [`generator.py`](generator.py) writes a
`.env.example` file containing a hardcoded `DATABASE_URL` with a plaintext
password (`secret`).

## 2. Mock Variable Isolation — Current State

### 2.1 What the code actually does

The phrase "mock database variable isolation" describes the intent to prevent
development-only credentials and service references from reaching production.
The current implementation provides **partial** isolation.

#### `generator.py` — `.env.example` generation

```python
# generator.py, lines 24-29
sample_env_content = (
    "# Auto-Generated by CodeMap AI via IBM Bob 2.0 Agent Core\n"
    "PORT=8080\n"
    "DATABASE_URL=postgresql://postgres:secret@localhost:5432/dev_db\n"
    "ENVIRONMENT=development\n"
)
with open(".env.example", "w") as env_file:
    env_file.write(sample_env_content)
```

**What is isolated correctly:**
- The filename is `.env.example`, not `.env`. A `.env.example` file is
  conventionally committed to version control as a documentation template and
  is **not** loaded by any runtime library automatically.
- The `ENVIRONMENT=development` marker clearly scopes the file to dev use.

**What is not isolated:**
- The password `secret` is hardcoded as a literal string in source code
  (`generator.py` line 27). Any developer who has read access to the repository
  can see this credential — defeating the purpose of the `.env.example`
  pattern.
- The function writes the file unconditionally to the **current working
  directory**, which may be the repository root, a mounted container volume, or
  any path depending on where the script is invoked.
- There is no check to prevent overwriting an existing `.env.example` that a
  developer may have customised.

#### `main.py` — service mock map

```python
# main.py, lines 36-54
response_data = {
    "dependencies": [
        {"source": "Stripe Gateway",  "target": "Local Mock Port 8081", "type": "AUTO_PROVISIONED"},
        {"source": "AWS S3 Cluster",  "target": "Local MinIO Bucket",   "type": "AUTO_PROVISIONED"},
        {"source": "PostgreSQL DB",   "target": "SQLite Isolated Dev DB", "type": "LOCAL_FALLBACK"}
    ]
}
```

This payload is a **static, hardcoded dictionary** — not the result of any
runtime environment inspection. It does not read from `.env` files, does not
connect to any external service, and does not proxy any live credential. The
mock service references (`Port 8081`, `MinIO`, `SQLite`) are safe to return to
any authenticated (or currently unauthenticated) caller.

### 2.2 Isolation boundary summary

| Variable / credential | Location | Reaches runtime? | Isolated? |
|-----------------------|----------|-----------------|-----------|
| `DATABASE_URL` with plaintext password | `generator.py` line 27 | Written to `.env.example`; not auto-loaded | ⚠ Partial — password is readable in source |
| Mock service port references | `main.py` lines 50-53 | Returned in API response; no live connection | ✅ Safe — static strings only |
| `BACKEND_URL` (Docker build arg) | `docker-compose.yml` line 57 | Compile-time Next.js build arg; internal DNS only | ✅ Safe — `http://backend:8000` is not routable externally |
| `ENVIRONMENT` flag | `docker-compose.yml` line 35 | Injected as container env var | ✅ Safe — default `development`, overridable |

## 3. Token Provisioning Flow

The `/api/provision-sandboxes` endpoint in [`main.py`](main.py) returns a
static list of log strings. **No token generation, secret injection, or
subprocess execution occurs** in the current code:

```python
# main.py, lines 63-72
return {
    "status": "success",
    "logs": [
        "[TokenFlow] Intercepting blocked database connection string...",
        "[IBM Bob 2.0 Subagent] Spinning up local isolated SQLite container cluster...",
        "[TokenFlow] Injecting simulated Stripe payment verification keys into local .env...",
        "[Success] Sandbox environment is fully live! Dev onboarding wait time reduced to 0 days."
    ]
}
```

These strings are documentation-style output only. No `.env` file is written,
no subprocess is launched, and no external API is called by this route. The
log message "Injecting simulated Stripe payment verification keys" is
descriptive text — it does not reflect any code execution.

## 4. Identified Security Issues

The following issues are present in the current code and must be addressed
before any production deployment.

---

### 4.1 Path Traversal in `/api/analyze-structure` — **HIGH**

**Location:** [`main.py`](main.py), lines 29-33

```python
raw_path = request.project_path.replace('"', '').replace("'", "").strip()
target_path = os.path.normpath(raw_path)

if not os.path.exists(target_path):
    raise HTTPException(status_code=400, detail="Target path does not exist.")
```

**Issue:** The endpoint accepts an arbitrary filesystem path from an HTTP
request body and passes it directly to `os.path.exists` (and by extension
`os.walk` in any future implementation). A caller can supply
`project_path: "/workspace/../../etc/passwd"` or any other path accessible
inside the container.

The Docker volume mount in [`docker-compose.yml`](docker-compose.yml) exposes
the entire host workspace at `/workspace` with `read_only: true`. While
`read_only` prevents writes, it does not prevent reading arbitrary files from
the mounted tree.

**Remediation:**
```python
import pathlib

ALLOWED_ROOT = pathlib.Path("/workspace").resolve()

def safe_path(raw: str) -> pathlib.Path:
    target = (ALLOWED_ROOT / raw.lstrip("/")).resolve()
    if not target.is_relative_to(ALLOWED_ROOT):
        raise HTTPException(status_code=400, detail="Path is outside the allowed workspace.")
    return target
```

### 4.2 Unauthenticated API — **HIGH**

**Location:** [`main.py`](main.py), lines 8-14

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**Issue:** Every endpoint is reachable by any origin with no authentication
requirement. `allow_origins=["*"]` combined with `allow_credentials=True` is
also an invalid CORS configuration — browsers reject credentialed cross-origin
requests when the origin is a wildcard. This does not protect the API; it only
breaks browser clients that attempt to send cookies.

**Remediation:**
- Add an API key or bearer-token check via a FastAPI dependency before any
  route handler executes.
- Restrict `allow_origins` to the exact frontend origin
  (`http://localhost:3000` for local development; the production domain
  otherwise).
- Remove `allow_credentials=True` unless cookies are explicitly required.

---

### 4.3 Hardcoded Credential in Source — **MEDIUM**

**Location:** [`generator.py`](generator.py), line 27

```python
"DATABASE_URL=postgresql://postgres:secret@localhost:5432/dev_db\n"
```

**Issue:** The password `secret` is a string literal in a committed source
file. Even though it targets a dev database, hardcoding any credential in
source normalises a dangerous pattern and risks accidental reuse.

**Remediation:** Replace with a placeholder that makes the template intent
explicit and cannot be mistaken for a real credential:

```python
"DATABASE_URL=postgresql://postgres:<REPLACE_WITH_DEV_PASSWORD>@localhost:5432/dev_db\n"
```

Consider adding a pre-commit hook (e.g. `detect-secrets` or `gitleaks`) to
block future credential literals from being committed.

---

### 4.4 Unconditional File Overwrite — **LOW**

**Location:** [`generator.py`](generator.py), lines 31-33

```python
with open(".env.example", "w") as env_file:
    env_file.write(sample_env_content)
```

**Issue:** The file is opened in `"w"` (write/truncate) mode with no existence
check. Running `generator.py` a second time will silently discard any manual
additions a developer made to `.env.example`.

**Remediation:** Check for existence before writing, or open in exclusive
creation mode (`"x"`) and handle the `FileExistsError` gracefully.

---

### 4.5 Next.js Rewrite Proxies to `localhost` — **LOW**

**Location:** [`codemap-ui/next.config.ts`](codemap-ui/next.config.ts), line 8

```typescript
destination: "http://localhost:8000/api/:path*",
```

**Issue:** This rewrite target resolves to `localhost` on the machine running
the Next.js dev server. Inside a Docker container, `localhost` refers to the
container itself, not the backend service. The Docker Compose file correctly
passes `BACKEND_URL: http://backend:8000` as a build argument, but
[`next.config.ts`](codemap-ui/next.config.ts) does not use this variable —
it hardcodes `localhost:8000`. The rewrite will fail silently when the frontend
is run inside Docker.

**Remediation:**

```typescript
// codemap-ui/next.config.ts
const BACKEND_URL = process.env.CODEMAP_BACKEND_URL ?? "http://localhost:8000";

const nextConfig: NextConfig = {
  async rewrites() {
    return [{ source: "/api/:path*", destination: `${BACKEND_URL}/api/:path*` }];
  },
};
```

## 5. Container & Network Isolation

The Docker Compose configuration in [`docker-compose.yml`](docker-compose.yml)
provides the following isolation guarantees:

| Control | Configuration | Assessment |
|---------|--------------|------------|
| Service network | `codemap-net` bridge network, both services attached | ✅ Backend is not directly reachable from the host network; only port `8000` is published |
| Workspace mount | `read_only: true` bind mount of `.` to `/workspace` | ✅ Prevents container writes to the host filesystem |
| No secrets in image | No `ENV` with credentials in [`Dockerfile.backend`](Dockerfile.backend) | ✅ Credentials are not baked into the image layer |
| Unprivileged base | `python:3.12-slim` | ✅ Minimal attack surface; no unnecessary OS packages |
| Health checks | Both services have `healthcheck` blocks | ✅ `depends_on: condition: service_healthy` prevents frontend from starting before backend is ready |

**Gap:** The backend container runs as `root` by default because no `USER`
directive appears in [`Dockerfile.backend`](Dockerfile.backend). Add a
non-root user to reduce blast radius if the container is compromised:

```dockerfile
RUN addgroup --system appgroup && adduser --system --ingroup appgroup appuser
USER appuser
```

## 7. Remediation Checklist

Address items in the order listed. Items marked **HIGH** must be resolved
before any internet-facing deployment.

- [ ] **[HIGH]** Add path-confinement validation to `/api/analyze-structure`
  to restrict traversal to `/workspace` (§4.1)
- [ ] **[HIGH]** Add authentication middleware to all API routes and restrict
  CORS `allow_origins` to known frontend origins (§4.2)
- [ ] **[MEDIUM]** Replace hardcoded `secret` password in `generator.py` with
  a `<placeholder>` string and add a secrets-scanning pre-commit hook (§4.3)
- [ ] **[LOW]** Guard `.env.example` write in `generator.py` against
  overwriting existing customisations (§4.4)
- [ ] **[LOW]** Read `CODEMAP_BACKEND_URL` from the environment in
  `next.config.ts` instead of hardcoding `localhost:8000` (§4.5)
- [ ] **[LOW]** Add a non-root `USER` directive to `Dockerfile.backend` (§5)
